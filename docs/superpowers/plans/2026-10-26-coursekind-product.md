# Coursekind Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a locally verified goal-to-plan-to-study workspace with bounded AI generation, reviewable revisions, conflict-safe restore and optional Jev advisory review, preserving all existing learning journeys/data.

**Architecture:** Add owner-scoped workspace, proposal, job and change-set documents over the existing JSON/SQLite storage contracts. Reuse course/module/path services, access rules, immutable provider selection and exactly-once generation accounting; generation produces staged outputs, and typed transactions apply them only after review. A single-process runner persists work before inference and exposes polling/recovery without automatic repeat after unknown outcomes.

**Tech Stack:** Existing Python/FastAPI/Pydantic/asyncio backend, JSONStorage and SQLiteStorage, React/TypeScript/TanStack Query/Tailwind frontend, pytest/Vitest/Playwright, existing httpx provider transport. No new agent framework or queue service.

**Spec:** [Coursekind product design](../specs/2026-10-26-coursekind-product-design.md). Also read [baseline journeys](../../user-journeys.md) and [Jev research](../../product/jev-integration-research.md). Spec and plan travel together.

## Global Constraints

- Display name is Coursekind; repository name, existing routes, storage paths, persisted IDs and all user data remain intact.
- All 40 active baseline journeys and D1–D8 remain supported. AI-06/Codex subscription stays deferred after the failed CLI isolation qualification.
- Anvil `llm.primary` remains the default; existing selectable Anvil models and BYOK OpenAI/Gemini/Anthropic remain. Snapshot provider/model once per job; never silently fall back.
- Local Anvil costs: plan, plan refinement, or course metadata/outline/path-reference AI refinement 10; full module or lesson/full-module revision 25; flashcard generation/revision 8; quiz generation/revision 10; apply/restore/manual editing 0. Successful BYOK operations record zero Anvil debit; external charges may apply.
- New workspace plans contain one course or 1–3 courses in a path, with 1–6 proposed modules per new course and at most 18 new modules. Existing manual/library sizes are not restricted by these bounds.
- Build defaults to one module and allows at most three selected modules sequentially. Default requested activities are 5 flashcards and 3 quiz questions; workspace counts allow 1–20 flashcards and 1–10 quiz questions when enabled. Existing optional activities and configured practice remain supported.
- Persist job/step state before provider calls; save validated outputs with accounting and replay identity. Unknown outcomes after restart require explicit retry with an external-charge warning; do not automatically repeat inference.
- Both concrete JSONStorage and SQLiteStorage transactions are supported and tested; never use the abstract pass-through transaction as an atomicity guarantee. Single-process limits remain; no distributed or JSON multi-file power-loss atomicity claim.
- Every context read, polling read and apply checks current ownership/access. New workspace/artifacts are private. Reuse preserves original authorship and never grants source edit access.
- Changes are typed allowlisted proposals with review, atomic apply, history and conflict-safe restore. No arbitrary shell tools, split/merge, automatic destructive replacement, or undo that deletes newly created objects.
- Jev is optional explicit advisory review using `jev-1.14.0`; no Anvil debit, no score/completion/authorization effect, no invented prose from probability-only answers. Backend-only `TYPESAFE_API_KEY` never enters browser payloads or logs.
- No merge, public deployment, repository rename, domain purchase, or trademark-clearance claim is part of local completion.

## Review Focus

- A formerly authorized reused source is revoked after generation: polling/history/replay must not disclose its retained derived output (Task 2 access-revocation test).
- A baseline manual editor changes content while an AI proposal is open: apply and restore must conflict even though that editor does not know workspace versions (Task 3 fingerprint test).
- A crash occurs after provider output but before a success response: completed receipts replay without calls/debits; indeterminate work stays interrupted until explicit retry (Task 2 restart/receipt test).
- A batch is cancelled while its active call returns valid output: retain an explicitly charged ready draft, launch no next step and apply no live changes (Task 2 cancellation test).
- A restored quiz/card deck has old learner history and a stale Jev review: preserve history/IDs, recalculate current deck using D8, and mark review stale rather than certify the restored content (Tasks 3 and 4 tests).

## Shared interface decisions

All new IDs are UUID strings; times are UTC ISO strings; owner is always from authenticated user, never caller-supplied JSON. Pydantic models use `extra='forbid'` for action requests. Collections: `workspaces`, `workspace_plans`, `workspace_jobs`, `workspace_steps`, `workspace_changes`, `workspace_revisions`, `workspace_reviews`. Additive document storage needs no destructive migration.

`ResourceTarget(kind: Literal['course','module','path'], resource_id: str, course_id: str | None)` and `ResourceSnapshot(target, fingerprint: str, fields: dict)` are defined in `models/workspace_change.py` by Task 2. `course_id` is mandatory for a module. Hash canonical sorted JSON of allowlisted editorial fields, including ordered membership when relevant. `snapshot(user_id: str, target: ResourceTarget, *, editable: bool) -> ResourceSnapshot` in `workspace_context.py` checks AccessService and excludes progress/sharing/accounting. Every dependent task uses this exact function contract.

No provider credentials go into persisted snapshots or Job responses. `ProviderSnapshot` remains the existing runtime object. Extend `GenerationOperation.run(..., provider_snapshot: ProviderSnapshot | None = None)` and its internal `_run` backward-compatibly: use supplied immutable selection when present, otherwise retain existing preference lookup. Do not change historical accounting/replay behavior. Workspace jobs capture the runtime snapshot once at start; retry is a new attempt with a new visibly selected snapshot. Persist provider/model labels only. Provider calls and spawned runner tasks begin outside transaction scopes.

Endpoint prefix `/api/v1/workspaces`; frontend routes `/workspaces` and `/workspaces/:workspaceId`. Use existing api client/error semantics. Jobs return HTTP 202; polling only reads persisted state and never starts or resumes inference. All mutation requests carry stable client-generated `request_id`; repeated same key+input returns original result, differing input returns 409. Task 1 brief PUT additionally uses `expected_version` for stale-write protection. For every replayable mutation, authenticate/check current access, then resolve matching request_id/input replay before comparing expected versions; a lost-response retry returns its original result even after that successful write incremented the version.
